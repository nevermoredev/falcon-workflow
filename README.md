# Falcon Workflow

Учёт рабочего времени и задач небольшой команды. Менеджер ставит задачи и расставляет приоритеты, сотрудники берут их в работу и ведут таймер. Готовую работу проверяет ревьюер, а по итогам строятся отчёты по каждому человеку.

Стек: PHP 8.5, Laravel 13, PostgreSQL 18, Bootstrap 5. Без сборки фронтенда: стили и скрипты лежат в `public/`.

## Быстрый старт

Нужен Docker (Docker Desktop на Windows и macOS).

```bash
git clone <repo> falcon-workflow
cd falcon-workflow
docker compose up -d --build
```

Через полминуты приложение доступно на http://localhost:8000.

При первом запуске контейнер сам:

- создаёт `.env` из `.env.example` и генерирует `APP_KEY`;
- дожидается Postgres;
- применяет миграции;
- заполняет пустую базу демо-данными.

Данные хранятся в docker-томе `pgdata` и переживают перезапуск. Загруженные файлы лежат в `storage/app`.

Остановить:

```bash
docker compose down
```

Начать с чистой базы (удалит все данные):

```bash
docker compose down -v && docker compose up -d --build
```

## Без Docker

Нужны PHP 8.4+ (с `pdo_pgsql`, `intl`, `zip`), Composer и PostgreSQL.

```bash
composer install
cp .env.example .env        # указать DB_* своей базы
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve
```

Если удобнее, Postgres можно поднять из того же compose (порт 5432 проброшен наружу):

```bash
docker compose up -d db
```

## Тесты

## Что умеет

**Менеджер**
- Доска в 4 колонки: к выполнению, в работе, на ревью, готово. Сортировка по приоритету и дедлайну, просроченное подсвечено.
- Список всех задач с фильтрами: поиск, приоритет, метка, исполнитель, статус, «только срочные», «только просроченные».
- Создание задачи в стиле Trello:
  - цветные метки, новые можно ввести прямо в форме;
  - описание и чек-лист;
  - файлы и скриншоты;
  - приоритет, дедлайн и ревьюер;
  - родительская задача и дочерние задачи.
- На одну задачу можно назначить нескольких исполнителей, у каждого свой участок. Участок можно передать другому человеку: таймер остановится, в обсуждении останется запись о передаче. Исполнителя можно снять с задачи.
- Разделы «Команда» (сотрудники и должности) и «Метки».

**Сотрудник**
- Вкладки: мои задачи, общая очередь (можно взять задачу себе), задачи на моём ревью, история выполненного.
- Срочное, просроченное и возвращённое на доработку выводится отдельным блоком сверху и выделено в карточках.
- Таймер работает без перезагрузки страницы и виден в меню на любой странице. Время считается на сервере, поэтому закрытая вкладка ничего не теряет. Два таймера одновременно запустить нельзя, даже из разных вкладок.
- «Сдать на ревью» сам останавливает таймер. Ревьюер принимает работу с оценкой 1–5 или возвращает с комментарием, возвраты считаются.
- Комментарии к задаче целиком или к своему участку.

**Отчёты** (за выбранный период, по умолчанию последние 3 месяца)
- **Обзор:** создано и закрыто задач, часы, доля сданного в срок и принятого с первого раза, динамика по неделям, что просрочено сейчас.
- **Сотрудники:** карточка на каждого и рейтинг из 100 (40% — сроки, 30% — приём без возвратов, 30% — оценка ревьюера).
- **Время:** часы по неделям на человека, самые затратные задачи, полный лог.
- **Дедлайны:** что сдано с опозданием и на сколько, что просрочено сейчас, что горит на неделе.
- **Качество и ревью:** нагрузка на ревьюеров, время до проверки, частота возвратов, задачи с наибольшим числом возвратов.
- **По меткам:** объём, часы, просрочки и возвраты по направлениям.
- Личный отчёт по сотруднику: часы по неделям, текущие задачи, последние замечания ревью, вся история.

## Устройство

```
app/Http/Controllers/
  DashboardController   доска менеджера и рабочий экран сотрудника
  TaskController        задачи, участки, ревью, чек-лист, комментарии, фильтры
  TimeEntryController   таймер (JSON для фронта + обычные формы)
  ReportController      все отчёты и личный отчёт
  TeamController, TagController
app/Models/             Task, TaskAssignment, TimeEntry, TaskChecklist, TaskMaterial, TaskComment, Tag, User
database/seeders/       демо-история «Блокнота»
resources/views/        Blade-шаблоны
public/css/app.css      стили
public/js/timer.js      живой таймер
docker/entrypoint.sh    старт контейнера
```

Основные сущности:

- **Задача** (`tasks`) — описание, приоритет, дедлайн, метки, родительская задача.
- **Участок** (`task_assignments`) — кто и что делает в задаче, кто ревьюит, статус (`todo → in_progress → submitted → rework/done`), число возвратов, оценка.
- **Запись времени** (`time_entries`) — привязана к участку. Статус задачи считается из статусов её участков.

## Что изменилось относительно первой версии

- Вместо простого таймера с текстовым описанием — полноценные задачи: приоритеты, дедлайны, чек-листы, вложения, метки, подзадачи.
- Несколько исполнителей на задачу, передача участков, ревью с оценкой и подсчётом возвратов.
- Отчёты по качеству и срокам, личные отчёты, рейтинг сотрудников.
- Живой таймер без перезагрузок, защищённый от двойного запуска.
- Раздельный интерфейс с боковым меню, новый дизайн в фирменной зелёной палитре.
- Переезд с SQLite на PostgreSQL 18, обновление до PHP 8.5 и Laravel 13, контейнер Postgres в `docker-compose.yml`.

### Примеры запросов

Реальные запросы, сокращены:

> Надо, чтобы менеджер давал задачи и расставлял приоритеты, сотрудник мог забирать задачу, запускать и останавливать таймер, а после завершения видеть нормальный лог. Отчёты тоже продумать: кто задачу дал, кто выполнял. Менеджер может передать задачу другому. У задачи, как в Trello: описание, материалы, скрины, чекбоксы.

> Добавь ревью: пройдено или не пройдено, кто ревьюит. Одну задачу могут делать несколько исполнителей одновременно, но разные части.

> Добавь дедлайны и оценку работы: выполнение в срок, сколько раз возвращали с ревью. Отчёты под каждого сотрудника.

> Сделай в сидах историю за 3 месяца: дизайнер, фронтендер, бэкендер делают приложение-блокнот, с косяками со стороны сотрудников. У разработчиков ревью делает тимлид, у дизайнера — PM.

> Можно таймер сделать без перезагрузки и чтобы дырок не было?

> Подними Postgres, Laravel и PHP до актуальных версий.

### Какие ошибки нашёл и исправил

| Что было | Причина | Исправление |
|---|---|---|
| Страница задачи падала с синтаксической ошибкой Blade | `/5@endif` — Blade не распознаёт директиву сразу после буквы или цифры | Добавил пробел перед `@endif` |
| Приёмка работы без комментария отдавала 500 | Обращение к ключу `review_comment`, которого нет в провалидированных данных | `$data['review_comment'] ?? null` |
| Чек-лист при редактировании склеивался в мусор | При генерации кода потерялись обратные слэши в регулярке `\r\n` | Восстановил регулярку и прогнал тест на добавление пунктов |
| После остановки таймера часы откатывались назад | Отработанный интервал не прибавлялся к уже залогированному времени на клиенте | При остановке интервал переносится в «залогировано» |
| Можно было запустить два таймера (двойной клик, две вкладки) | Проверка и вставка без блокировки | Транзакция с `lockForUpdate` по пользователю. Повторный старт той же задачи ничего не делает, старт другой отдаёт 409 |
| Эпики (задачи с подзадачами) попадали в общую очередь, их можно было «взять» | Очередь выбирала все задачи без исполнителей | Из очереди исключены задачи с подзадачами |
| После Laravel 13 все POST в тестах отдавали 419 | Docker передаёт `APP_ENV=local` через `$_SERVER`, а `<env>` в phpunit его не перебивает, поэтому CSRF не отключался | В `phpunit.xml` добавлены `<server ... force="true">` |
| Тесты в контейнере стёрли рабочую базу Postgres | По той же причине `RefreshDatabase` работал с боевым подключением | Тесты принудительно идут на SQLite в памяти, демо-данные перезалиты |
| Контейнер не стартовал: `entrypoint: not found` | В `entrypoint.sh` были переводы строк Windows (CRLF) | Перевёл файл на LF, добавил `.gitattributes` |
| Сайт в Docker отдавал 500 на вход | `artisan serve` перечитывает `.env`, а там `DB_HOST=127.0.0.1` вместо `db` | `entrypoint.sh` прописывает в `.env` настройки БД из docker-compose |
| Ожидание Postgres зацикливалось | `db:show` падал без расширения `intl` | Проверка подключения через PDO, в образ добавлен `intl` |
| Поиск по-разному работал в SQLite и Postgres | `like` в Postgres чувствителен к регистру | Заменил на `whereLike` (без учёта регистра в обеих БД) |

  - таймер, комментарий, сдача на ревью;
  - возврат на доработку, повторная сдача, приёмка с оценкой;
  - все вкладки отчётов и личный отчёт;

  - фильтры сотрудника.

Кроме тестов, каждую страницу и каждую задачу обошёл под всеми пятью ролями на реальной базе Postgres: ошибок нет, закрытые разделы отдают 403.
